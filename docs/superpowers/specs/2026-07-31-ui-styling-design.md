# UI Styling Design — learn-react

**Date:** 2026-07-31
**Status:** Approved

## Goal

Replace the debug scaffolding in this React learning project with an intentional
visual design. The UI should document what it demonstrates: each hook exercise
becomes a labeled card, so the page reads as a lab notebook for React hooks.

## Current State

- Next.js 16.2.12 (App Router), React 19.2.4, Tailwind CSS 4.3.3.
- Tailwind is installed and imported in `app/globals.css` but effectively unused.
- `app/page.tsx` styles itself with debug values: inline `color: red`,
  `backgroundColor: green`, and a `.section` rule applying `outline: 1px solid red`.
- `app/globals.css` sets `body { font-family: Arial, Helvetica, sans-serif }`,
  which overrides the Geist fonts `app/layout.tsx` loads via `next/font/google`.
- `app/home.module.css` holds a single `.border` rule.
- `app/about/page.tsx` is an unstyled heading plus a link.
- Root metadata is still the scaffold default: title `"Create Next App"`,
  description `"Generated by create next app"`.

## Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Visual direction | Hooks lab / devtools | The UI labels which hook each demo exercises, so it doubles as documentation for a learning repo. |
| Styling mechanism | Tailwind v4 utilities over `@theme` tokens | Already a configured dependency; no setup cost. Responsive grids and state variants are single words. Most transferable skill. |
| Dark mode | Semantic CSS vars flipped in `prefers-color-scheme`, surfaced through `@theme inline` | Utilities like `bg-surface` resolve to a var that changes with the media query, so **no `dark:` variants are needed** for base surfaces. One place to edit each theme. |
| Scope | Full — tokens, shell, both pages, all components | Leaving half the app in debug colors would look broken. |

### Why `@theme inline` and not `@theme`

`@theme inline` inlines the token's *value* at use sites rather than emitting a
reference chain. Combined with `--color-surface: var(--surface)`, a utility
compiles to `var(--surface)` — so redefining `--surface` inside the dark media
query re-themes every consumer with no variant classes. Plain `@theme` would
snapshot the light value and break the flip. The existing scaffold already uses
this pattern; the design extends it rather than replacing it.

## Design Tokens — `app/globals.css`

Cool grays with a single indigo accent. The accent lightens in dark mode so it
retains contrast against a dark surface instead of going muddy.

| Token | Light | Dark | Use |
|---|---|---|---|
| `--background` | `#fbfbfc` | `#0a0a0b` | Page canvas |
| `--surface` | `#ffffff` | `#141417` | Card and nav fill |
| `--border` | `#e6e7eb` | `#26262b` | Hairline rules |
| `--foreground` | `#17181c` | `#ededed` | Primary text |
| `--muted` | `#6b7280` | `#9095a1` | Secondary text, hook badges |
| `--accent` | `#4f46e5` | `#818cf8` | Buttons, active nav, emphasis |

Exposed as `--color-*` inside `@theme inline`, plus `--font-sans` /
`--font-mono` bound to the existing Geist variables.

**Cleanups:** delete the `.section` outline rule; remove `font-family: Arial` so
Geist applies; delete `app/home.module.css`. Deleting the module also requires
dropping its `import styles from "./home.module.css"` in `app/page.tsx` and the
`className={styles.border}` it feeds to `<Header>` — the border is now the
`Card` / `Header` treatment, not an ad-hoc rule.

## Components

Each unit below has one purpose and a stated interface.

### `app/components/Nav.tsx` — new, client component

- **Does:** sticky top bar; `learn-react` wordmark left, Home/About right,
  hairline bottom border. Active route rendered in the accent color.
- **Interface:** no props.
- **Depends on:** `usePathname` from `next/navigation`, `next/link`.
- **Why separate:** isolating `usePathname` here keeps `layout.tsx` a server
  component instead of pushing the whole shell across the client boundary.

### `app/components/Card.tsx` — new, server component

- **Does:** renders a mono hook badge, a title, then children, inside a rounded
  `bg-surface` panel with a hairline border.
- **Interface:** `{ hook: string; title: string; children: React.ReactNode; className?: string }`
- **Depends on:** nothing.
- **Why:** the repeated unit of the whole design. Centralizing it means the
  visual language changes in one file, not five.

### `app/layout.tsx` — modified

Renders `<Nav />` above a centered `max-w-3xl` column with vertical padding.
Metadata updated to a real title and description.

### `app/components/Header.tsx` — modified

Page-title treatment: large `font-semibold` heading, muted subtitle, bottom
rule. **Public API unchanged** (`text`, `textSubtitle`, `className`).

### `app/components/Description.tsx` / `List.tsx` — modified

`Desc` becomes a `Card`; `List` renders a bordered row instead of a bare `div`.
`List` keeps its `description` prop.

### `app/page.tsx` — modified

Responsive `grid sm:grid-cols-2 gap-4` of cards:

1. **`useState`** — large tabular-nums counter, accent Increment button, and a
   progress line toward the success threshold.
2. **`useRef`** — text input plus a Focus button.
3. **`useMemo`** — full-width (`sm:col-span-2`); shows the cached result and a
   Recalculate button.

### `app/about/page.tsx` — modified

Same shell, real heading and body copy, styled back-link.

## Behavioral Changes

Styling requires rendering values that are currently computed but never read.
That surfaces three real issues, each an intentional change:

1. **Render `income`.** Clears the `'income' is declared but its value is never
   read` hint and gives the `useMemo` card something to show.
2. **Wire `setShouldCalculate` to a Recalculate button.** The one genuine feature
   addition. Without it `shouldCalculate` never changes, so `useMemo` has no
   observable behavior and the card would be inert. It also makes memoization
   demonstrable: Increment logs nothing, Recalculate logs `Calculation....`
3. **Fix the success off-by-one.** `handleClick` tests `counter === 10` against
   the pre-update value, so `success` flips at 11. Once the card renders a
   success state this is visible on screen, so the check becomes
   `counter + 1 === 10`.

## Non-Goals

- No new dependencies. No component library, no icon package, no animation library.
- No routing or data-fetching changes.
- No refactor of the hook demos into separate files — they are the subject of the
  exercise and stay in `app/page.tsx`.
- No class-based (manual toggle) dark mode. System preference only; a toggle
  would need state and persistence, which is out of scope for a styling pass.
